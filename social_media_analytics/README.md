# Аналитика данных продуктового приложения

Учебный проект, моделирующий работу аналитика данных в продуктовой команде. В качестве объекта исследования используется мобильное приложение, состоящее из ленты новостей и мессенджера.
Для анализа используются события пользователей из базы данных ClickHouse (события ленты и сообщения пользователей).

В рамках проекта решены задачи, максимально приближенные к тем, с которыми сталкивается junior/middle Product Data Analyst:
- анализ A/B-тестов
- исследование поведения пользователей и retention
- разработка аналитических дашбордов 
- автоматизация ETL-процессов в Airflow
- прогнозирование продуктовых метрик
- автоматическая отчетность в Telegram
- система мониторинга и алертов

Используемый стек
- Python
- SQL (ClickHouse)
- Pandas
- NumPy
- SciPy
- Matplotlib
- Seaborn
- Airflow
- Orbit
- Telegram Bot API


Содержание проекта: 

### **1. Анализ A/B-теста CTR**
Проверка гипотезы о влиянии нового алгоритма рекомендаций на CTR. 

Использованы:
- t-test
- Mann–Whitney U test
- Poisson Bootstrap
- Smoothed CTR
- Bucket Transformation

Получено сравнение методов анализа продуктовых метрик и их чувствительности к особенностям распределения CTR.

### **2. Продуктовая аналитика**
Включает несколько независимых задач.

**Дашборд взаимодействия сервисов** 

Построен аналитический дашборд, описывающий использование ленты и мессенджера

**Анализ рекламной кампании** 
- исследование retention пользователей
- сравнение рекламного и органического трафика
- интерпретация причин низкого удержания

**Новые, удержанные и ушедшие пользователи** 

Построена недельная динамика пользовательской базы с разделением пользователей на три категории

### **3. ELT-пайплайн в Airflow**
Разработан DAG, ежедневно собирающий агрегированные метрики пользователей из нескольких таблиц ClickHouse и загружающий их в итоговую витрину.

Используются срезы:
- OS
- пол
- возраст

### **4. Прогнозирование активности пользователей**
Построена модель прогнозирования количества действий пользователей в ленте приложения на месяц вперед с использованием библиотеки Orbit.

Использованы:
- DLT
- MCMC
- бинарный регрессор для учета рекламной кампании и флешмоба.

### **5. Автоматизация отчетности**
Разработан Airflow DAG, ежедневно отправляющий в Telegram:
- основные продуктовые метрики
- динамику за последнюю неделю
- автоматически построенные графики

### **6. Мониторинг аномалий**
Реализована система автоматического контроля продуктовых метрик.
Используются:
- Holt-Winters
- Rolling Window
- IQR

При обнаружении аномалии Telegram получает уведомление с графиком и описанием проблемы.
